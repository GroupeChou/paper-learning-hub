    摘要¶

    图表资源¶

    1 引言¶

    大语言模型的快速进展催化了从被动式问答接口到自主智能体的范式转变。多智能体系统（MAS）在复杂问题求解中展现的远超单一 LLM 的能力。

    然而，MAS 的有效性关键依赖于其文本参数的精确配置。智能体工程师不仅要精心设计单个智能体的系统提示，还要设计工具描述、智能体间通信协议和整体工作流。这个过程——智能体工程——代表了一个高维度、非结构化的优化挑战。

    现有方法的不足¶

    1. 缺乏结构感知：现有自动提示优化（APO）方法聚焦于"平面"提示优化，无法处理多智能体架构中的复杂交互
    2. 静态无记忆：优化器不学习——它们执行搜索但缺乏从过去失败中学习以改进自身优化策略的机制

    本文贡献¶

    1. TPGO 框架：首个将 MAS 优化视为图进化问题的框架，支持复杂 Agent 架构的结构和语义优化
    2. 文本参数图（TPG）：将单一文本配置分解为模块化、可单独优化的语义单元
    3. 群体相对智能体优化（GRAO）：一种自进化的元优化策略，利用历史经验持续改进优化提案质量
    4. 实验验证：在 MCP-Universe 和 GAIA 上显著增强 SOTA 智能体系统

    2 相关工作¶

    语言智能体系统：从 ReAct（单智能体框架）到多智能体系统（MetaGPT、MaCTG）。MAS 引入大量设计选择——协作结构、通信协议、角色人格。

    自动提示优化：搜索方法（PromptAgent + MCTS）、进化算法（EvoPrompt）、梯度方法（TextGrad）。共同限制：关注文本内容而非系统架构，无法修改交互结构。

    3 问题定义¶

    MAS 配置由文本参数 Θ 定义（系统提示、工具描述、交互规则）。给定任务分布 T = {(q_k, a_k)}，系统 A(Θ) 产生输出 â_k 并生成执行轨迹 τ_k。

    目标：找到最大化性能的最优文本参数集 Θ*

    \[\Theta^* = \arg\max_{\Theta \in S} \mathbb{E}_{(q,a) \sim T} [R(A(\Theta, q), a)]\]

    其中 S 是巨大的离散非结构化文本配置空间。

    4 方法论¶

    4.1 TPGO 概览¶

    TPGO 在闭环循环中运行，包含三个核心阶段（图 2）：

    1. 图构建：将单一提示分解为透明的、模块化的 TPG
    2. 梯度驱动进化：从执行轨迹中派生"文本梯度"语义反馈信号
    3. GRAO（群体相对智能体优化）：使优化器自身从经验中学习和改进的元优化层

    4.2 文本参数图（TPG）¶

    图结构 G = (V, E)

    节点类型： - 角色节点（Role Nodes）：Agent 的核心人格、高层目标、战略指令 - 逻辑节点（Logic Nodes）：具体推理协议、操作约束、思维链过程 - 工具节点（Tool Nodes）：功能描述、API 规格、使用示例

    边：建模依赖和逻辑流——智能体内流、工具集成、智能体间通信。

    基于图的优化操作： - REWRITE_NODE(v, new_content)：修改节点内容 - PRUNE_EDGE(u, v)：移除连接以禁用故障路径 - ADD_NODE(v_new, content)：引入新技能或约束 - ADD_EDGE(u, v)：建立新依赖或逻辑流

    4.3 梯度驱动进化¶

    文本梯度：结构化的自然语言批评和建议，通过三阶段过程指导图的进化。

    步骤 1：轨迹诊断与梯度生成 - 执行 MAS 以收集轨迹集 T = {τ₁, ..., τ_N} - 正梯度 δ⁺：从成功轨迹提取，归纳有效行为模式 - 负梯度 δ⁻：从失败轨迹提取，精确定位错误并提出修正建议

    步骤 2：梯度聚合（聚类） - 对负梯度进行语义聚类，识别系统性错误模式 - 使用 DBSCAN 聚类，无需预设聚类数量

    步骤 3：生成和应用优化提案 - 对每个错误聚类，优化器 LLM 生成具体优化提案 ΔG - 提案包含具体的图编辑操作集合

    4.4 自进化优化（GRAO）¶

    GRAO 使优化过程自身自进化——从过去优化的效果中学习以产生更好的提案。

    验证与效果评分： 对每个提案 ΔG 在相关任务子集上验证，计算效果分数 E(ΔG) ∈ [0,1]

    优化经验记忆： 每次优化尝试记录为 (问题上下文 C, 解决方案提案 ΔG, 结果 E)

    自适应提案生成： 新错误出现时，从记忆中检索语义相似的历史经验，按效果排名后作为少样本示例注入优化器 LLM，使其生成更高质量的新提案。

    5 实验¶

    5.4 优化稳定性（GRAO 效果）¶

    图 3：有/无 GRAO 的优化稳定性对比 - 有 GRAO：第 3 轮稳定提升至 33.74% 后保持稳定 - 无 GRAO：第 2 轮峰值 30.03%，第 4 轮骤降至 14.55%（灾难性遗忘）

    GRAO 通过缓解灾难性遗忘同时提高了最终性能和优化鲁棒性。

    5.5 跨域泛化¶

    仅在浏览器自动化上优化后，在其他三个未见领域上评估：Web 搜索 +1.82、Repo 管理 +2.73、3D 设计 +3.13。表明 TPGO 学到的是通用改进而非领域特定修复。

    5.6 成本效益分析¶

    一轮优化：1990万 tokens，1380秒（8路并发），每轨迹分摊 73.7K tokens/5.6秒。优化后 agent 执行时间从 4014 秒降至 1765 秒（-56%）。

    6 案例研究：不完整约束验证修复¶

    失败模式：Agent 识别了正确答案（Ollie Watkins）但仅验证了 4 个约束中的 2 个，过早得出结论。

    TPGO 诊断：提取的负梯度——"Agent 在找到'足够好'的候选后停止调查的行为倾向"

    图级修正：添加新角色节点"约束验证协议"，要求： 1. 列出所有约束 2. 创建验证清单 3. 用具体证据验证每个约束 4. 仅在所有约束验证通过后才提供最终答案

    效果：修正可迁移到其他多约束问题，是一个任务无关的推理过程改进。

    7 结论¶

    TPGO 通过结构化图进化而非平面提示调优来改进智能体系统。通过将 Agent 配置分解为模块化文本组件、使用执行导向的文本梯度信号精化它们、以及通过 GRAO 利用优化记忆，TPGO 实现了更稳定和更有效的 Agent 优化。

    局限性： - 无形式化优化保证（文本梯度是启发式反馈而非解析梯度） - 优化循环成本较高（每提案需验证） - 依赖底层 LLM 的解析、诊断和提案生成能力 - 当前限于文本参数优化，未考虑数值超参数或更大结构变化
